# 職涯導航：資料與第一版設計

使用者需求：Agent 建議職涯路線，以及值得補足的技能、經驗與證照；台灣及美國市場都支援，優先控制平台成本。

## 第一版做法

以使用者已確認的經驗、目標、時間／預算／地點限制，對照目標職缺與官方職能資料，提出 2–3 個可比較方向。採用檢索資料後生成建議，不需先 fine-tune 模型。

使用者選擇職缺分組 → 去重並依地區與資歷整理 JD → 抽取明示的必要／加分條件 → 比對經驗證據 → 先追問不明資料 → 產生成長計畫 → 完成後回寫經驗庫 → 更新履歷與找工條件。

## 已查驗的來源

| 資料 | 來源 | 用法及限制 |
| --- | --- | --- |
| 美國職業、技能、任務與相關職業 | [O*NET](https://www.onetcenter.org/database.html) | 可下載 CSV、JSON、SQL 等格式，作為職業與技能基礎；使用時遵循授權與例外。相關職業不代表實際轉職成功路徑。 |
| 台灣職能基準 | [iCAP](https://icap.wda.gov.tw/ap/resources_datum.php) | 提供職能基準查詢，選擇現行版本並記錄日期；本次未確認有可供產品大量匯入的開放 API 或授權，不假設可任意鏡像。 |
| 國際職業技能標準化 | [ESCO](https://esco.ec.europa.eu/en/use-esco) | 可下載資料並使用 API，作為職稱與技能關係的補充；以歐洲為背景，不直接當台灣招募需求。 |
| 美國職業發展與入行条件 | [BLS OOH](https://www.bls.gov/ooh/occupation-finder.htm) | 補充職業層級的教育、訓練與就業展望；不能解讀成個人的錄取或升遷概率。 |
| 美國職業執照 | [CareerOneStop](https://www.careeronestop.org/Developers/WebAPI/Licenses/list-licenses.aspx) | API 需申請憑證與使用授權；各州資料覆蓋不完整，最終資格需回主管機關查驗。 |
| 台灣技術士職類 | [技能檢定中心](https://www.wdasec.gov.tw/News_Link.aspx?n=2D1D6B951B8541BC&sms=4C9F24535BA50B1F) | 使用職類檢定規範與最新正式資訊；不涵蓋所有專業執業資格。商業證照另查發證機構。 |
| 當前雇主需求 | 使用者提供的 JD、企業招募頁與取得使用授權的職缺來源 | [Greenhouse Job Board API](https://docs.greenhouse.io/job-board.html) 的 GET 不需認證；這是特定企業職缺來源，並非完整市場資料。不要把可讀取視為無限制再散布授權。 |
| 成員面經與求職結果 | 個人資料與明確授權分享的內容 | 可作補充；自填、樣本偏差、不同地區／資歷等因素使其不適合直接推論證照的因果效益。 |

## 建議必須包含的證據

- 證據類型：本人確認、職缺明示、官方職能基準、成員經驗或 Agent 推論。
- 來源 URL、摘錄、發布／更新日期、抓取時間、適用市場、職位與資歷。
- 職缺樣本去重後的總數及條件提及數；只稱「此樣本的提及率」，不可稱全市場比例。
- 缺口狀態：已具備且有證據／做過但尚缺證據／尚未提供、需要追問／本人確認沒有相關經驗。
- 證照種類：法定執業資格、該雇主必備、雇主加分、尚無支持證據。資格、費用、有效期與地域適用性向主管機關或發證機構查驗。
- 每個成長任務連回需求，定義可驗收的產出，例如專案、工作成果、程式碼、測試與技術說明；不把練習專案寫成任職經驗。

## 控制成本

公用職能資料按照其更新週期維護；職缺內容按版本抽取並快取，變更時才重做。先用查詢與規則做初篩，再由使用者自己的 AI 產生個人化說明。網站背景自動化採使用者 API key；MCP 模式從使用者自己的 Claude 發起。不承諾訂閱能代付任意後台 API 呼叫。

先支援少數明確職類及使用者收藏的目標職缺；資料不足就詢問或降低建議強度。資料整理與評估品質比先購買大型人才履歷庫更適合作為 MVP 工作。
