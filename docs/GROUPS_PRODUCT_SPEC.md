# 職缺分組與求職小組

使用者已選擇：兩者結合，按職類分組，也能邀朋友加入。

## 產品規則

1. 個人分組按照職責、技能、资歷、地點整理同類型工作；AI 可建議分組，使用者可以調整。
2. 每個分組有「我未投遞、我已投遞、已略過」檢視；草稿、待補資料與佇列中仍屬未送出。
3. 共用小組保存共享職缺池、逐職缺討論與主動分享的面經。範例小組有四位成員，不代表人數限制。
4. 同一職缺在組員之間共享一份職缺資訊，但每位成員的申請狀態獨立。別人投過不會把職缺從我的未投清單移除。
5. 組員已投、面試中或獲得 Offer 只有在本人開啟分享時才顯示；未分享代表未知，不可推斷為未投。
6. 履歷、完整經驗、信箱與 Offer 金額預設私人。面經逐篇分享，原始錄音與附件不自動公開。
7. 加入小組、收藏職缺或分享連結不代表授權投遞。每個人使用自己的資料與投遞規則；管理員不能替成員授權。
8. 小組管理員可管理邀請與成員，不因此取得其他人的私人求職資料。

## 資料關係建議

- Job：共用職缺，保存來源、外部識別碼、正規化網址與開放狀態。多來源的同一職缺應去重；不同職位或不同 requisition 不可只因公司相同而合併。
- JobCollection / CollectionJob：個人分組與職缺關聯。
- Group / Membership：小組、成員與角色。
- GroupJob：共用職缺與分享者、分享時間。
- Application：綁定 user_id + job_id，追蹤個人狀態及不可變的已投履歷快照；加入小組不複製或重建申請。
- InterviewNote / NoteShare：個人面經與指定的小組分享授權，分享內容可選擇整理版，保留原始資料私人。
- GroupSharingPreference：每人、每小組的狀態分享選項。
- Invitation：有期限、可撤銷的加入憑證；本次 Figma 邀請網址僅為示例。
